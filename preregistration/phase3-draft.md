# 第三阶段实验方案（草稿，2026-10-08；第二阶段结果出来后补空再预注册）

研究对象不变：DSH 0.2.0-rc.2、v41flash（推理强度 max）、DeepResearch Bench II 中文 66 道题、GPT-5.5（high）主判、Opus 复判两成、同一套跑批/提取/判分/行为标注流水线（批名 p3-*）。第二阶段回答"两个上限该设多少"；第三阶段回答"除了上限，harness 还能动哪几个杠杆、每个值多少"。四个模块都是 harness 开发者第二天就能改的设置，文献里一个都没有对照数。

标"【待填】"的地方等第二阶段的数出来再定，定了以后整份文件和格子文件一起冻结提交，再开跑。

## 一、四个问题

| 模块 | 问题 | 杠杆 | 来源 |
|---|---|---|---|
| P 先规划再派活 | 主 agent 在开 subagent 之前先写出分工（每个 subagent 的目标、范围边界、交回格式、不做什么），质量和重复分工会不会变，多花多少 | 提示句；或把开 subagent 的工具改成必填这四个字段 | Anthropic 说这是最大的改进，没给数；Cursor "specifying intent" |
| R 交回的形式 | subagent 把发现写成文件、只交回路径加三行摘要，对比现在整段消息交回：事实到达报告的比例、主 agent 的上下文、费用 | harness：给每个 subagent 的任务末尾加一条固定规则 | Anthropic 附录"文件代替传话"没测；我们第一阶段"交回丢失"的疑问 |
| S 派不派的策略 | 只把能并行、范围宽的子任务交给 subagent，窄的和有顺序依赖的自己做，对比默认和第二阶段的 O（只派不干） | 提示句 | GitHub Copilot CLI 的做法（工具失败少 23%、等待少 5%），不是对照实验 |
| Q 排队代替拒绝 | 名额满时让开 subagent 的调用等一个名额，而不是报错拒绝：被拒的那一半调用是浪费还是本来就不该开 | 改 DSH 一处（名额池 reserve 改成带超时的等待） | 我们第二阶段：开 subagent 的调用约一半被拒；Claude Code 是报错让模型别重试 |

## 二、格与规模

每个模块一批，同批有自己的默认格作参照（不跨批合并）。题：66 道中文题各 1 次（质量半宽约 2.1 分），Q 用 40 道（两个 K 各一格，半宽约 3 分）。

| 模块 | 格 | 运行 | 运行费（按第二阶段单价推算） |
|---|---|---|---|
| P | 默认 K=8；P1 提示版（题面末尾加分工要求）；P2 工具版（开 subagent 工具必填 objective、scope、output_format、not_in_scope 四个字段，harness 把它们拼进子任务开头） | 66 × 3 | 约 1,500 元 |
| R | 默认 K=8；R 文件交回（每个子任务末尾由 harness 追加："把全部发现写到 findings/<你的名字>.md，交回时只写文件路径和不超过三行的摘要"；主 agent 题面加一句"subagent 的发现在 findings/ 目录里，写报告前先读"） | 66 × 2 | 约 1,000 元 |
| S | 默认 K=8；S 选择性委派（题面末尾加："只把能并行、范围宽的子任务交给 subagent；窄的、有先后依赖的自己做"） | 66 × 2 | 约 1,000 元 |
| Q | 【待填：从第二阶段的需求曲线挑两个确实卡住的 K】候选：自然需求 K=2（第一阶段卡住 67% 的运行）配拒绝 / 配排队；固定需求 8 配 K=4 配拒绝 / 配排队 | 40 × 4 | 约 1,600 元 |
| 合计 | | 518 | 约 5,100 元；判分约 1,100 次调用走公司额度 |

每一格为什么在：P1 对 P2 分开"要求写分工"和"harness 强制填字段"两种实现；R 只有一格，因为交回形式只有文件和消息两种；S 和第二阶段的 O 合起来是"不派、只派、选择性派、模型自定"四档；Q 的两个 K 分别代表模型自己想开（自然需求）和被要求开（固定需求）。

附加句和 harness 改动在开跑前各做 4 题 × 2 次校准（P2 看字段是否都填了、R 看文件是否都写了、Q 看排队是否真的等到名额），只按比例改一次。

## 三、指标

质量、费用、时间、交付同第二阶段。每个模块另看它自己的机制量，全部从日志和第二阶段的行为标注流水线出：

| 模块 | 机制量 |
|---|---|
| P | 重复分工率（同胞打开网页的重叠率、同一查询来自不同 agent 的次数）；子任务说明的长度和四个字段的有无；交回被用上的比例（relay 判分：交回里的事实进了报告多少） |
| R | 交回丢失（relay 判分）；主 agent 的未命中输入 token；findings/ 文件数和字数；报告里引用到 findings 的比例 |
| S | 开成数；主 agent 自己的搜索占比（planner_self_work）；时间 |
| Q | 被拒 → 排队的调用数；平均排队时长；放弃的子任务数；用户等的时间 |

## 四、分析

每个模块一个确认性对比（质量，备选格对默认，两格分层模型，Holm 在四个对比的家族内校正）：P 取 P2 对默认（P1 作探索），R、S 各一个，Q 取固定需求 K=4 的排队对拒绝。判断用词同第二阶段：优效、显著更差、没测出加排除范围。费用、时间、机制量只报估计和区间。

预期【待填：用第二阶段的数写】。现在能写的方向：P 的重复分工率下降、费用持平或略升；R 的交回丢失下降、主 agent 未命中 token 下降；S 的费用下降、质量没测出差别；Q 的时间上升、被拒调用归零、质量【待填】。

## 五、工程准备（第二阶段判分期间做）

- P2：补丁模块（像 dsh-told 那样换掉容器里的 dsh-tool-subagent），工具参数加四个必填字段，拼进子任务开头；phase2_check 式的校验脚本。
- R：补丁模块给每个子任务末尾追加固定规则；主 agent 读 findings/ 的句子走附加句机制。
- Q：补丁模块把名额池的 reserve 改成等待（超时【待填】分钟后仍按原样拒绝并记录）；校验脚本查日志里"排队开始/结束"的记录。
- 三个补丁各做 1 次冒烟，在本机运行时离线验证能加载。

## 六、顺序与时间

P → R → S → Q，每批一夜加半天判分；Q 的工程在第二阶段判分期间做完。四批串成一条链一次启动，门同第二阶段（结构校验、校准达标、并发）。约四天出数。

## 七、第二阶段出数后要填的空

1. Q 的两个 K；2. 四个模块的预期值；3. P1 的句子是否保留（如果 O 模块显示角色句本身就改变行为，P1 和 O 的句子要分开写）；4. 题数是否从 66 减到 40（看第二阶段质量方差）；5. 第二阶段行为标注里哪几项和结果相关，作为 P、S 的机制量优先报。
